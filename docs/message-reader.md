## 在 VS Code 中逐项验证

1. 确保前后端运行的是最新代码。若未运行，终端一在项目根目录执行：

   ```bash
   .venv/bin/python -m uvicorn app.main:app --reload --app-dir backend --host 127.0.0.1 --port 8000
   ```

   终端二执行 `npm --prefix frontend run dev`，打开 `http://127.0.0.1:5173`。不要重复启动占用相同端口的进程；手动重启后端前先确认没有正在运行的采集任务。
2. 刷新页面 → “消息” → 顶部选择已有账号、群聊、日期，立即生效。需要跨天/关键词等精确条件时展开“高级筛选与批量操作”，修改后点搜索。无需重新扫码、绑定或采集。
3. 左侧成员显示当前基础范围的完整统计。点击两位成员，确认两者高亮且结果为这两人的联合发言；“清除成员”恢复全部。相同昵称按 `#用户ID` 区分。
4. 点击两个小时条，确认只展示两个小时的消息；点击已选小时取消，或“清除小时”。跨天查询的小时条是多天累计，不是某一天独立统计。
5. 点击媒体“图片 / 视频 / 链接”。一条含多种附件的消息可同时属于多个快捷分类。如果结果意外为空，检查高级附件/用户/关键词或日期范围；“全部”清除所有类型条件，不清除其他维度。展开“筛选与附件统计”查看当前范围与附件总数。
6. 切换“隐藏噪声”，核对摘要数量与列表差异；关闭后恢复。当前规则为已入库系统/红包标记，完整短句“早、早安、早上好、晚安、大家早、大家早上好”，以及“昵称加入了群／群聊”的完整单行通知（允许昵称与提示间空格、首尾空白和句末句号/感叹号）。带后续正文或多行内容的入群讨论保留。不包含 auto 的全部问候/纯标点正则；采用保守规则，不隐藏包含正文的问候句。
7. 在任意消息点“上下文”。右侧只显示该账号、群与删除状态的相邻消息，键盘焦点进入侧栏；窄屏为可关闭的覆盖侧栏。点击关闭或在侧栏按 Esc 返回原按钮。点“查看更早/更新上下文”只在右栏翻页，到边界禁用；可回到原消息。
8. 在一条被筛选隐藏的记录点“跳到列表”，主列表显示“定位阅读”并聚焦目标。点击“返回筛选列表”，检查原筛选、分页和滚动恢复。定位期间禁用批量删除/恢复/彻底删除或导出，避免范围混淆。
9. 链接只显示安全地址，作者/正文/互动预览与缺失提示卡片已按新需求取消。原消息正文和附件详情仍保留，存量数据不删除。图片原件预览、灯箱、Base64 入库不在本次实现中。
10. 在“正文查找（保留上下文）”输入词语，等待约 200ms。正文匹配文字高亮，列表不会被裁剪；点击前后匹配可循环导航，未加载目标同样进入定位阅读。高级“关键词”是服务端结果筛选，包含附件标题/地址等；两者用途不同。
11. 回到筛选列表，点击“导出当前筛选结果”。打开下载的 `weibo-chat-filtered.txt`，核对账号/群、时间、作者、正文及附件地址。导出包含未加载分页，不包含仅查找高亮所指定的限制。TXT 是聊天明文，分享前自行脱敏。
12. 回收站重复只读步骤，确认不混入普通消息。不要为了验收而批量删除真实记录；删除/恢复范围使用隔离自动测试验证。

## API 契约

原 `GET /api/messages` 增加可选 `viewer` 查询参数；它是 JSON 编码的字符串。所有原删除/恢复预览及执行请求的 `filters.viewer` 使用相同字符串，因此不是仅浏览器本地筛选。

```json
{
  "members": [7, 8],
  "hours": [10, 12],
  "media": "links",
  "hide_noise": true,
  "hide_join_notices": false
}
```

- 省略时保持旧行为。members 最多 500 个正整数；hours 最多 24 个 0–23 整数；media 只能为空、photos、video、links；未知键/非法 JSON/越界返回 422，不静默扩大范围。
- 图片按 image 标准类型或 image 附件；视频按 video 类型/附件或完整“分享视频”“Video”占位文本；链接按 link 类型/附件、正文 HTTP(S) 或视频类型/附件。仅占位文本、没有视频地址的记录不会因此自动进入链接分类。标准类型作为兼容回退，数据结构并非直接使用 auto 的 pics/videoUrl/share 字段。
- 列表每项增加 `link_previews`；只返回 url/title/author/text/reposts/comments/likes。普通列表不会为每条消息发额外网络请求，也不返回整个 raw_payload。
- 同日简化修订后，前端只使用上述元数据的安全 URL，不再显示丰富预览。匹配的 `message_type` 与 `viewer.media` 视为同一媒体条件，冲突返回 422；省略 viewer 的旧标准类型筛选仍为精确类型。

新增只读端点：

| 端点 | 请求/返回 |
| --- | --- |
| `POST /api/message-view/facets` | `{filters, deleted_only}` → `{members, hours[24], hidden_noise}` |
| `GET /api/message-view/{id}/context` | 必填正整数 account_id/group_id，可选 deleted_only、direction=center/older/newer → `{target_id, account_id, group_id, deleted_only, direction, items, has_older, has_newer}`；错范围 404，非法方向 422 |
| `POST /api/message-view/matches` | `{filters, deleted_only, query, offset, limit}` → `{items, total, offset}`；query 1–300 字符，limit 1–200，offset 非负；前端每次只取一个匹配位置 |
| `POST /api/message-view/export` | `{filters, deleted_only}` → UTF-8 TXT 下载响应；不接受列表分页作为截断条件 |

基础成员/小时统计忽略 viewer 中的成员、小时、媒体与噪声条件，保留原账号/群/日期/用户/关键词/标准类型/附件条件，避免选中一项后其他选项消失。噪声数量则按当前全部条件、临时关闭噪声开关后计算。它们与正文列表总数不是相同统计口径。

修订补充：快捷媒体同时发送的标准类型别名也从基础统计中排除；仅单独发送标准类型时仍保留该限制。

facet/context/matches/export 使用只读 SQLite 快照。导出逐行读取，超过 1MB 的临时内容转磁盘暂存，响应迭代结束关闭临时文件；浏览器仍需接收完整 Blob 才下载。没有百万消息规模性能承诺，建议限定账号、群和日期。取消浏览器请求不保证服务器 SQLite 查询立即中止。

## 安全及未扩大的范围

- 新端点不调用微博、不读取账号 Cookie、不修改消息、采集、断点或附件文件。头像是浏览器按已保存 HTTP(S) 地址加载，禁用 referrer；缺失/失败回退首字。不是账号 Cookie 代理，也不保证头像源长期有效。
- 链接只允许 HTTP(S) 且拒绝带用户名/密码地址；前端以 React 文本渲染，原 HTML 不执行。原文中已有私人内容仍属于导出内容，不能把“无 Cookie 字段”等同于自动脱敏。
- 高置信度采集过滤早已丢弃的消息无法通过关闭噪声开关恢复。既有引用完整文字定位仍非微博源 ID 确认；重复文本不猜测。
- 上下文支持独立方向翻页和回到原消息，仍为有界窗口，不是无限滚动全量拼接、永久引用关系、多级浏览历史栈或自动补采集。
