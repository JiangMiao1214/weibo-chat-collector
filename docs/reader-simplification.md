2026-09-13 更新：消息与上下文改为旧到新，引用入口和附件展示去重，新增按账号读取图片的受控入口。最新契约与验证见 [消息展示修复](message-display-fixes.md)。

日期：2026-09-12。以本次六张截图（前两张相同）的批注为验收要求。本次调整取代首轮阅读器中的丰富链接预览与重复类型筛选设计，不扩大采集范围。

## 已修改

1. **右侧上下文真正翻页。** 原“查看更早上下文”调用主列表跳转；目标已加载时看起来没有反应。现在独立请求更早/更新的 5 条，不包含游标消息，不关闭侧栏、不改变主列表或批量操作范围。到边界按钮禁用，可“回到原消息”；请求失败显示错误及重试。
2. **白底、阅读优先布局。** 顶部只放账号、群、日期和高级入口；左侧只放成员；中间占用剩余高度并独立滚动。右栏默认不显示，点击“详情”或“上下文”才打开，可关闭。移除占空间的重复状态条、说明行和吸顶日期遮挡；筛选摘要与附件统计默认折叠，附件总数仍在摘要标题可见。
3. **顶部日期立即生效。** 选择日期直接查询当天 00:00:00–23:59:59，同时更新成员和小时统计；“全部日期”清除日期限制。跨天查询保留在高级筛选中，需点击搜索。小时条按选定范围累计，不自行假定今天。2026-10-21 起仅在日期范围实际生效后显示；全部日期时整个小时区隐藏，并同步清除小时条件。
4. **类型入口去重。** 图片/视频/链接统一为快捷按钮；文本/文件/系统放入同一工具条的“更多类型”，不再有左侧重复类型下拉框。“全部”清除所有类型条件。选择文件等类型时“全部”不会错误高亮。切换账号/群立即查询，同时清除旧成员、小时、媒体/类型和噪声条件，其他高级条件保留。
5. **取消丰富链接预览。** 消息气泡内只显示去重后的安全 HTTP(S) 地址，不再生成作者、正文、转评赞及“未存储链接正文”卡片。原消息正文和附件详情保留；数据库存量数据不删除，后端白名单元数据字段为兼容保留，不自动联网补抓。

## 后端契约变化

`GET /api/message-view/{id}/context` 增加可选 `direction=center|older|newer`（默认 center），账号/群仍必填，删除状态仍严格隔离：

- center：目标本身及前后各最多 5 条，与原接口兼容。
- older/newer：以 `{id}` 为游标，取严格更早/更新的最多 5 条；同秒使用消息 ID 排序，响应统一从新到旧。
- 前端翻早页用当前末条、翻新页用当前首条作为游标；返回 `direction`、`has_older`、`has_newer`，不会在主列表拼接结果。
- 错账号/群/删除状态返回 404；未知方向返回 422。它不是无限滚动或浏览历史栈。

快捷媒体请求保留 `message_type=link/image/video` 以兼容原前端测试与协议，同时发送对应 `viewer.media=links/photos/video`；这一对字段视为**同一媒体条件**，不再重复取交集。只传标准类型的旧请求仍使用精确类型口径。两者冲突返回 422，列表、导出、删除预览与执行共用该规则，不默默扩大删除范围。

成员/小时基础统计排除快捷媒体及其标准类型别名，防止“文本含链接”消息被别名条件漏掉；保留账号/群/日期/高级条件。仅单独传标准类型的旧 API 查询仍限制基础统计。隐藏噪声数量按实际完整过滤范围计算。

## TDD 过程与检查规则说明

修改前基线为 92 后端、47 前端测试。

## 在 VS Code 中验收

1. 确认没有采集任务运行。若后端未启用自动重载，在原后端终端 `Ctrl+C` 后执行：

   ```bash
   .venv/bin/python -m uvicorn app.main:app --reload --app-dir backend --host 127.0.0.1 --port 8000
   ```

2. 前端终端执行 `npm --prefix frontend run dev`；已有 Vite 服务无需重复启动。浏览器刷新页面，进入“消息”。无需重登、重新采集或迁移数据库。
3. 顶部选择账号、群和一个已有消息的日期，无需再点搜索。检查日期、消息时间和小时条一致；点“全部日期”恢复跨天阅读。
4. 点击成员、小时、图片/视频/链接，确认立即筛选；高级筛选中不再出现重复类型。统计请展开“筛选与附件统计”。需要关键词精确筛选或跨天范围时，展开高级筛选，输入后点搜索。
5. 找一条前后有足够历史的消息点“上下文”，连续点“查看更早上下文”，确认右栏的时间/内容变化且主列表不变。再点“查看更新上下文”“回到原消息”。到边界应灰掉按钮；“跳到列表”仍是另一个独立操作。
6. 关闭侧栏，确认消息区变宽；点击详情/附件再打开。检查长列表只有消息区滚动、日期不遮挡正文；在窄屏侧栏覆盖展示，可关闭后继续阅读。
7. 点击链接筛选，确认无作者/正文/转评赞/缺失提示卡片，只保留正文、链接和附件入口。真实链接能否打开仍取决于微博鉴权与地址是否过期。
8. 不要为验收批量删除真实消息。删除、恢复、跨账号拒绝等使用隔离自动检查：VS Code“任务：运行任务 → TDD: 完整验收”，或者根目录执行 `.venv/bin/python scripts/verify.py`。

## 后续修复：详情栏右侧空白（2026-09-12）

用户后续截图指出详情正文过窄、右侧留白。原因是外置的“关闭详情”使用右浮动，与正文的滚动容器布局相互作用，309px 可用栏宽被压成 209px。

- 先在现有隔离浏览器流程新增宽度断言，观察到 `可用 309px，实际 209px` 的业务失败，再修改组件和样式。
- 关闭按钮移入详情标题行，取消浮动；详情使用纵向弹性布局，标题固定在正文上方，正文/附件独立滚动并使用完整栏宽。
- 同一回归覆盖桌面和 390px 窄屏：正文占满可用宽度、无横向溢出、按钮属于标题行且不遮挡正文。保留全部原有业务断言，没有修改门禁或降低阈值。
- 本轮只改前端布局，不涉及后端、数据库或采集。刷新前端后点击“详情”，检查正文和附件不再只占左侧狭窄区域；窄屏验证截图在 `.tdd-results/ui/reader-detail-mobile.png`。

## 后续修复：消息底部空白与外层误滚动（2026-09-12）

后续截图中消息区底部大块留白，同时顶部账号/日期与小时条被裁掉。用 82 条模拟消息、40 个成员复现后发现：引用的 `scrollIntoView` 连带滚动了裁切的外层工作区（实测 `scrollTop=200`，预期为 0）；成员侧栏继承旧版 `align-self:start`，长内容未被限制在网格行高内，允许外层溢出。

- 先增加真实浏览器几何断言，观察到 `200 !== 0` 的业务红灯，再修复。之前两条消息的夹具不能覆盖该问题，本次保留全部旧流程并增加长列表场景。
- 已加载引用、正文搜索和上下文跳回列表共用 `focusMessageInList`：只计算并调整最近 `.message-list` 的滚动位置，键盘聚焦使用 `preventScroll`，不再对整条消息调用全祖先 `scrollIntoView`。超高消息定位到开头。
- 打开上下文只聚焦侧栏按钮，不再滚动外层；成员侧栏拉伸至当前网格行，成员列表自身滚动；顶部工具条不参与纵向压缩。
- 浏览器覆盖引用跳转、搜索定位、上下文打开/关闭、桌面 1366×800 和 390px 窄屏：工作区/消息面板滚动值保持 0，顶部范围选择可见，消息列表延伸到底部，长成员列表不溢出。另补 2 个滚动计算用例（普通消息/超高消息）。没有删除断言、放宽门槛或增加 skip。
- 实机验收：刷新前端，选择消息较多的群，点击引用匹配或搜索的“下一个匹配”；顶部账号/日期保持可见，中间列表独立滚动，底部不再出现因外层移位造成的空白。无需重启后端、重新扫码或采集。
