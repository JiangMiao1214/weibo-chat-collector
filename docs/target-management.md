# 账号与群聊管理

2026-10-21 更新：新增空账号删除、一账号一群限制及旧多群保留提示。

2026-10-09。新增独立桌面端“账号管理”和“群聊管理”入口。只处理本地资料；打开页面不会登录微博、创建采集任务或启动归档。状态每 10 秒刷新，也可手动刷新。

## 账号管理

- 新增账号不再要求同时填写群聊和群 ID；可维护名称、备注、启用状态。
- 汇总关联群聊、未删除消息数、各群最近采集状态和归档保存情况。
- 登录准备状态来自本机凭据文件检查，并明确标注未联网验证，不代表远端登录始终有效。
- “登录与采集”带上账号及其唯一群进入现有采集页（刷新仍保持该目标），用户再点击扫码；继续使用现有独立 Cookie、群 ID 发现与人工绑定流程。
- “查看账号消息”清空旧的日期、成员等筛选，按选定账号显示消息。
- “清除登录凭据”先展示确认说明。确认后只删除该账号的标准本机 Cookie 文件，保留账号、群和全部历史消息；停止排队任务并暂停归档。存在该账号扫码会话、运行采集或在途下载时拒绝清除，需先结束相应操作。

## 群聊管理

- 按所属账号筛选；每个账号最多配置一个群，停用群仍占用名额。新账号可暂时无群，显示“待配置群聊”。管理新增、备用目标配置、JSON/CSV 导入均在写事务内检查数量，不能通过并发请求绕过。
- 维护名称、备注、启用状态与数字微博群 ID；未绑定时群 ID 可留空，随后进入扫码绑定流程。
- 同账号不能重复绑定同一微博群 ID；不同账号可以分别保存自己有权访问的同一个群。
- 群所属账号不可更换。已有历史的群不能更换或清除已经绑定的微博群 ID；请保留原绑定；历史整理需另行确定方案。首次为未绑定记录填写群 ID 仍沿用既有确认方式。
- 显示未删除消息及附件数量、已入库最早/最晚时间、最近采集任务、归档开启/暂停及保存/等待/失败数量。日期范围不是完整采集覆盖证明。
- “查看消息”带上账号与群，重置旧筛选；“扫码绑定与采集”带上目标。归档入口复用现有本群归档面板。采集监控入口进入既有全局监控，页面明确标为“全部采集监控”。

## 删除空账号

账号卡片点“删除账号”，先展示目标账号、将删除的空群、本机凭据以及阻止原因，再点“确认删除本地账号”。取消不做修改，不涉及注销微博平台账号。没有群和没有凭据的账号同样支持删除。

用户确认的范围是：仅删除没有历史数据的账号、其空群和标准本机凭据。正常/回收站消息、附件、群成员、采集任务及断点、导入/快照/验证/删除记录、归档设置/任务/主机记录、OCR 设置/任务/文字结果、操作日志任一存在都拒绝删除；不默认清空这些记录。磁盘原件始终保留，包括其他账号可能共用的文件。

存在该账号扫码会话时拒绝删除；运行采集、归档或 OCR 的关联记录也会阻止删除。不会为删除自动停止正在进行的工作。确认时取得写锁并重新核对范围及预览指纹；账号/群资料、凭据或历史变化后必须重新预览。凭据文件必须是普通文件，不跟随符号链接；清理失败回滚数据库，数据库提交失败恢复暂存凭据。正常 Cookie 上传也在同一数据库写锁之后校验账号，避免账号删除后又写入凭据。

成功后刷新账号列表、群选项及消息/采集/验证的失效选择。删除不生成该已移除账号的孤立日志，不清理磁盘原件或自定义的外部凭据副本。

## 旧多群兼容

已有多群账号保留所有群、消息、断点和附件，页面显示“待整理”；不自动删除、合并或迁移，也不隐藏旧群。可以维护名称/备注/启停并继续查询、采集原目标，不能新增群或变更远端绑定。管理编辑、备用配置及扫码确认共用后端保护；前端禁用新增或改绑输入。不同账号仍可以分别配置同一个微博群。以后整理旧多群需要单独确定保留/迁移方案。

## 启停规则

1. 停用保留历史和原件，不执行删除。
2. 运行中的采集须先安全停止；扫码/绑定会话须先结束，管理页会返回可操作的错误提示。
3. 停用后将所选范围排队/待确认任务置为停止，并暂停归档。在途归档沿已有检查点停止，不把未完成文件标成成功。
4. 已停用账号或群不能确认/续传旧采集任务，也不能开启/恢复归档；归档领取任务还会再次检查启用状态。
5. 重新启用仅改变启用状态，不解除风险冷却，不自动恢复采集或归档。
6. 生命周期修改与本进程浏览器启动串行；检查浏览器会话后再取得数据库写锁，避免与浏览器事件保存/确认绑定的锁顺序相反。

原有“高级工具 / 数据导入”的配置入口保留。账号停用不影响本地历史查询、离线附件阅读或回收站操作。删除账号只允许无历史账号；消息历史的删除仍使用原有消息删除预览与确认流程。

## 接口与隔离测试

- `GET /api/management`：账号、群聊及本地状态汇总，不返回 Cookie 值或原始消息内容。
- `POST /api/management/accounts`、`PATCH /api/management/accounts/{id}`：资料与启用状态。
- `DELETE /api/management/accounts/{id}/credentials?confirmed=true`：显式清除本机凭据。
- `GET /api/management/accounts/{id}/delete-preview`：返回账号、空群、各类历史计数、凭据是否存在、阻止原因、可删除状态及 `preview_token`。
- `DELETE /api/management/accounts/{id}`：JSON `{confirmed: true, preview_token: "预览返回的值"}`；无确认 422，有历史/在途会话/预览变化 409，不存在 404；成功只删除空账号及空群和本机凭据。
- `POST /api/management/groups`、`PATCH /api/management/groups/{id}`：群资料和绑定检查。

测试先观察新端点 404、禁用账号仍可领取归档、浏览器检查持有数据库写锁等失败，再实现。自动验证只使用隔离 SQLite、临时凭据目录和模拟网络。前端覆盖资料保存、凭据确认、按群跳转；浏览器覆盖管理页面、修改账号和群消息跳转。实际结果见 `.tdd-results/fast/report.json` 与 `.tdd-results/full/report.json`。
