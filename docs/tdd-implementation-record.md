结构检查本轮扫描 31 个生产模块、356 个行数/函数测量项，通过；已有超限项显式记录，不能靠自动重生成基线把回归隐藏掉。重复检查目前为完整函数体级别。

真实红—绿证据：

1. 前端先新增“同一登录状态下 Cookie 从未就绪变为就绪，只刷新一次账号资料”。执行 `npm --prefix frontend test`：9 通过、1 失败，期望资料请求 2 次，实际 4 次。根因是轮询闭包一直读取旧的 `cookie_ready=false`。
2. 将轮询抽入 `useBrowserLoginPolling`，读取最新会话、串行处理请求，成功刷新后不重复刷新：原 10 个测试全部通过，再补充异步边界用例。
3. 新增“会话结束但资料刷新失败仍提示错误”后先观察到失败（错误回调 0 次），随后区分“停止轮询”和“组件卸载”，修复后通过，同时验证卸载后的迟到错误被忽略。

已有正常功能的回归测试首次就是绿灯，不故意破坏正式代码制造红灯。

## 4. 定向变异

每个变异在独立解释器内修改源代码的内存版本，先跑正常版本基线，再验证错误版本。四个基线通过，四个变异全部 `KILLED`：

| 故意注入的错误 | 拦截它的行为 |
| --- | --- |
| 移除账号筛选 | HTTP 账号单条件查询混入另一账号消息 |
| 附件总数错误地统计为消息数 | 两张图片所在消息不能只计一条附件 |
| 续传清零游标 | 同一任务应沿已提交检查点请求 |
| 取消重复判定 | 重复采集（含已软删除消息）不得重复落库 |

只接受目标业务测试的断言失败；导入失败、零测试、跳过、超时不计作有效拦截。源代码定位锚点变化时检查报错，需要人工审阅更新定位，而不是跳过变异。四个定向变异通过不等于全项目 100% 变异覆盖。
