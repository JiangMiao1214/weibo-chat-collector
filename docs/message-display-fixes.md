## 主列表加载更早消息时保留阅读位置（2026-10-20）

- 主列表每次最多读取 100 条符合当前筛选条件的更早消息；不足 100 条时返回剩余记录。按消息条数分页，不按分钟/小时分页，因此可能跨天。总数是全部筛选结果，已加载数逐页增加。
- 点击顶部“加载更早消息”后，新消息仍按旧到新插入上方，当前可见消息保持在原视口位置，用户自行向上滚动查看。此行为默认生效，不需要额外开关。
- 请求期间继续滚动时，以用户最新的可见消息和偏移量为准；加载失败、刷新替换、切换筛选/普通或回收站/定位阅读后，不应用旧分页位置。原来的消息选择、筛选、附件汇总及删除/导出范围不变。
- 实现使用布局阶段的消息位置补偿，并关闭主列表原生滚动锚定，避免浏览器重复补偿。日期分组使用稳定日期键，前插其他日期时不重新挂载已有日期下的消息和图片组件。右侧上下文的独立滚动逻辑不变。

浏览器夹具显式返回普通消息阅读，清除前序 OCR 定位样例留下的定位阅读状态；定位阅读禁止分页的原断言和产品行为保留。测试数据和网络均为隔离模拟，不访问真实数据库、Cookie、微博或附件原地址；未更改质量基线、门禁或添加 skip。

## 当前行为

- 主列表、定位阅读、右侧上下文和引用窗口统一按时间从旧到新显示；同秒按本地 ID 升序稳定排列。接口仍按倒序返回，原游标、筛选、附件汇总和删除范围不变。加载更早消息的按钮移到列表顶部；侧栏翻早页仍取接口末条、翻新页仍取接口首条。
- 引用在当前列表有唯一匹配时，仅保留原来的“查看匹配消息”；否则保留精简的“查看引用原文”入口，按需查询已入库消息。重复文本不自动选中，完整文字匹配与账号/群/删除状态隔离规则不变。这是对“引用处多了在已入库消息显示的内容”的界面解释；不是删除引用正文或已入库消息。
- 详情和引用窗口共用附件组件。同类型、同安全 URL（无 URL 时按本地路径）的重复元数据只显示一张卡片；没有地址的独立记录保留。标题与链接合并为一个入口，标题本身是网址时不再重复显示；图片入口显示“查看图片”。数据库附件记录及全筛选汇总不被展示去重修改。
- 支持的微博图片使用本地读取入口，点击时才请求。`upload.api.weibo.com/2/mss/msget` 使用附件所属账号保存的 Cookie，并按目标域名、路径、有效期筛选；Sina 图片 CDN 不携带账号 Cookie。请求带微博 Referer，解决直接跳转无法使用项目登录状态的访问路径问题。没有重新采集、缓存文件、迁移数据库或自动刷新图片地址。

## 图片读取 API

`GET /api/attachments/{attachment_id}/image?account_id=1&group_id=11&deleted_only=false`

- ID/账号/群必须为正整数；账号、群、删除状态和附件类型必须与数据库记录匹配，否则 404，且在此之前不读取 Cookie 或访问网络。源地址由数据库读取，不接受用户输入 URL 参数。
- 仅支持 HTTPS 的上述 msget 路径及编号 wx/ww/ws/tvax/tva 的 sinaimg.cn/com 图片主机。拒绝用户信息、非标准端口及其他主机；其他附件仍提供安全的 HTTP(S) 外链。
- 每跳都重新验证地址、重新按域名构造 Cookie；禁止 urllib 自动转发鉴权头。最多四次请求，每次 15 秒超时、最大 20 MB；只返回 JPEG/PNG/GIF/WebP/AVIF 类型，响应禁缓存并加 nosniff/CSP。重定向后的图片 CDN 不接收微博 Cookie。
- 缺失登录返回 401；源站 401/403 返回中文 403 提示重新登录所属账号或地址可能已失效；非图片/网络错误/跳转超限返回 502；超大图片返回 413。响应不转发上游错误正文、Cookie、签名地址或 Set-Cookie。
- 模拟测试不能证明真实历史地址仍有效。真实图片 403 是否完全消失，需刷新新版页面后点击原失败图片验证；地址过期、权限改变或登录失效仍可能失败。本轮未访问真实图片、读取真实凭据或执行采集。
