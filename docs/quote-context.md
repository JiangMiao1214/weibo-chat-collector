## 解决的问题

原消息已经入库，但不在当前加载的分页中，或被日期、关键词、用户、类型、附件条件筛掉时，可以点击引用块下方的“在已入库消息中定位引用”。后端在该消息所属账号、群聊和删除状态内查找，唯一匹配后显示目标及前后各最多 5 条相邻消息。

这项功能是完整文字匹配，不是微博源消息 ID 确认。当前采集结构没有可靠的被引用源 ID；重复原文时不猜测，也不使用本地数据库 ID 代替引用关系。

## 使用步骤（VS Code）

1. 保存代码并确认前后端加载了新版本。使用 `--reload` 的开发后端通常会自动重载；若需要手动重启，先确认没有运行中的采集任务。启动命令见 `run-and-debug.md`。
2. 刷新前端，进入“消息”，选择账号、群聊和日期，点击“搜索”。无需重新扫码或创建采集任务。
3. 找到 `「引用内容」 - - - 回复` 格式的消息。原有“查看匹配消息”仍只在当前已加载列表中定位；新增“在已入库消息中定位引用”会请求后端。
4. 点击新增按钮。窗口会明确显示账号、群、普通/回收站状态，并提示查找忽略日期等内容筛选。原列表条件不会被自动修改。
5. 唯一匹配时，绿色边框标出目标消息，显示时间、正文、附件元数据/原地址及相邻上下文。上下文总数最多 11 条，按新到旧排列；它不是自动加载整个群聊。
6. 没有匹配、引用格式不支持、存在重复候选或请求失败时会明确提示。不要把“未找到”理解为后台会自动采集；本功能不会访问微博。
7. 点击“返回原列表”或按 Esc，回到原位置。筛选、已加载分页、当前选中消息及批量删除范围保持不变，键盘焦点回到原定位按钮。
8. 回收站内同样可操作，但只能定位已删除消息，不会混入正常消息。普通列表不会搜索回收站。

## HTTP 契约

```text
GET /api/messages/{message_id}/quote-context?account_id=1&group_id=11&deleted_only=false
```

- 路径 ID 是发起引用的消息 ID，不是希望跳转的目标 ID。
- `message_id`、`account_id`、`group_id` 必须为正整数；账号/群参数必填。
- `deleted_only` 默认 false；true 表示引用消息、候选和上下文都必须已软删除。
- 服务端读取引用消息自身正文，不接受客户端指定引用文字/目标 ID。
- 原引用消息不存在、已彻底删除，或与请求账号/群/删除状态不一致，返回 404；非法参数返回 422。
- 候选必须同账号、同群、同删除状态，时间严格早于引用消息。同秒不推断源顺序；未识别格式不做模糊猜测。
- 比较完整原文，只统一 CRLF 换行与首尾空白；不使用 LIKE、短前缀或去除内部空格匹配。
- 查询使用单次只读快照，不改变消息、附件、筛选、任务、删除或去重数据；不返回 `raw_payload`。

成功响应中的字段：

| 字段 | 含义 |
| --- | --- |
| `source_message_id` | 发起引用的本地消息 ID |
| `account_id` / `group_id` / `deleted_only` | 实际查询范围，前端再次校验 |
| `match_method` | 固定 `full_text`，不声称源 ID 确认 |
| `status` | `matched`、`ambiguous`、`not_found` 或 `not_quote` |
| `target` | 唯一匹配的消息基础字段及 `attachments`；其他状态为 null |
| `items` | 目标及其前后各最多 5 条消息基础字段；其他状态为空数组 |
| `has_older` / `has_newer` | 此相邻窗口之外是否还有同范围消息，不是普通列表分页游标 |

多个候选时只确认“至少两个”，不返回候选正文或自动选择最近一条。上下文按 `sent_at DESC, id DESC` 排序；同秒 ID 仅用于稳定展示相邻记录，不用于判定谁引用了谁。

## 交互与性能边界

- 每次显式点击才查询，没有逐条后台扫描请求。React StrictMode 的探测挂载不会重复发出请求。
- 网络等待最多 15 秒；错误或超时后只接受用户手动重试，不自动重试。
- 关闭、卸载或切换引用身份时取消前端请求，迟到响应不会覆盖新状态。前端取消不等于服务器 SQLite 查询立即停止。
- 当前利用账号/群范围查询并逐条比较完整文字，没有新增全文哈希索引，也没有做大规模历史库性能承诺；结果集有界不代表查询成本恒定。
- 本次没有通用上下文翻页、多级引用导航、永久引用关系回填、浏览历史栈或自动补采集。窗口内相邻消息只供阅读，不改变原列表选中项。
- 图片仍是附件元数据和原地址，不是缩略图、本地缓存或 Base64 存储。
