# 网页版微博快照采集

更新时间：2026-08-12

## 当前目标

先对第一个账号和第一个群聊做安全的网页版采集试跑。

当前已知信息：

- 账号显示名：`微博账号A`
- 群聊显示名：`汉语从句研究会`
- 微博入口：网页版微博
- 采集时间段：`2026-06-15 17:00:00` 到当前时间

## 安全边界

当前方案不要求你提供微博密码、Cookie、Token、Authorization 或完整请求头。

做法是：

1. 你自己在浏览器里登录微博。
2. 你自己打开目标群聊页面。
3. 项目生成一段本地网页快照脚本。
4. 你在微博页面控制台运行脚本。
5. 脚本只读取当前页面可见文本块，并发送到本机 `http://127.0.0.1:8000`。
6. 项目保存快照到本地 SQLite 数据库。

脚本只负责保存原始“页面快照”，不会在接收请求里直接写正式消息表。保存后需要先在“高级工具 / 数据导入”中预览解析结果，再由用户显式确认导入；这样可以在写库前检查网页版 DOM 解析质量。

## 后端接口

### 生成网页快照脚本

```text
GET /api/browser-capture/snippet
```

参数：

- `account_id`
- `group_id`
- `range_start`
- `range_end`

### 接收网页快照

```text
POST /api/browser-captures
```

由微博页面中的脚本调用。

### 查看快照列表

```text
GET /api/browser-captures
```

### 预览解析和显式导入

```text
GET  /api/browser-captures/{capture_id}/parse-preview
POST /api/browser-captures/{capture_id}/import
```

预览不会写入正式消息表。只有用户检查结果并调用导入接口后，解析出的消息、用户、群成员和附件元数据才会在本地事务中入库。

## 你接下来要做什么

1. 确认后端和前端都已启动。
2. 打开前端：

```text
http://127.0.0.1:5173
```

3. 进入“高级工具 / 数据导入”。
4. 账号选择 `微博账号A`。
5. 群聊选择 `汉语从句研究会`。
6. 开始时间填写 `2026-06-15 17:00:00`。
7. 结束时间填写当前时间。
8. 点击“生成脚本”。
9. 点击“复制脚本”。
10. 回到已经打开的微博群聊页面。
11. 打开浏览器开发者工具 Console。
12. 粘贴脚本并回车运行。
13. 看到“已保存当前页面快照”提示后，回到前端点击“刷新快照”。
14. 对新快照执行“解析预览”，检查消息数量和样例。
15. 确认结果后再点击导入；红包和粉丝群标识会被过滤，普通问候照常入库。

## 运行快照后要确认

请确认最近快照列表里出现一条新记录，并记录：

- 快照 ID。
- 文本长度。
- 页面标题是否像目标群聊。
- 是否出现浏览器安全拦截或 CORS 错误。

如果出现 CORS 或 Private Network Access 错误，需要把错误提示告诉我，我再调整本地服务响应头。

## 当前限制

快照解析和显式入库已经实现，但微博网页版 DOM 可能随时变化。第一次处理真实页面时仍应先检查解析预览；若发送人、时间或正文识别不正确，不要执行导入。网页快照只是备用导入方案，主采集链路是全局串行的微博内部 JSON API 任务。
