# 回收站与已删除消息

更新时间：2026-10-21

回收站已复用 [明亮消息阅读器](message-reader.md) 的成员/小时/媒体/噪声筛选、上下文与 TXT 导出，所有读取仅在已删除状态中进行。新增 `filters.viewer` 条件同样约束恢复/彻底删除预览和执行；临时定位阅读期间禁用批量操作，返回原筛选后才可操作。

## 功能目标

回收站用于管理软删除消息。

普通消息列表默认只展示：

```text
is_deleted = 0
```

回收站只展示：

```text
is_deleted = 1
```

这样批量删除后，消息不会立刻从数据库消失，可以先在回收站查看和恢复。

## 已实现能力

- 切换“消息 / 回收站”视图。
- 回收站内复用账号、群聊、用户、日期、关键词、消息类型、附件筛选。
- 回收站内查看已删除消息详情。
- 预览恢复数量。
- 批量恢复当前筛选结果。
- 预览彻底删除数量。
- 二次确认后彻底删除当前筛选结果。

## 恢复逻辑

恢复会把消息重新放回普通消息列表：

```text
is_deleted = 0
deleted_at = NULL
```

附件记录会保留。

## 彻底删除逻辑

彻底删除只针对回收站中的消息。

执行顺序（TEST-005）：

1. 开启写事务，在删除任何关联记录之前，把当前筛选命中的回收站消息 ID 固定到连接内临时表。
2. 按这个固定集合删除附件记录、搜索索引、消息记录；不在附件删除后重新计算筛选。
3. 全部成功才提交，任一步失败整体回滚。数量来自同一事务内的固定集合，临时表不写入持久业务 schema。

有附件条件、附件标题/文件名/URL 关键词、仅附件命中的图片/视频/链接条件均遵守上述规则。普通消息、其他账号/群不属于删除范围。

当前不会删除磁盘上的图片和文件原件，避免误删文件。

## 预览与确认范围（TEST-006）

软删除、恢复和彻底删除的预览绑定操作类型、视图、规范化的已应用筛选及请求序号。账号、群、日期、筛选草稿或视图变化会撤销预览并取消在途读取；迟到成功、失败或超时都不能恢复旧确认。请求超时 15 秒后可重新预览，正在读取时媒体/成员按钮仍按既有规则禁用。

确认执行再次核对预览仍然有效，发送预览时保存的筛选快照；取消确认不发写请求。提交后消耗预览，禁止重复提交，不自动重试写请求；失败需重新预览。执行已发出后切换范围不会撤销服务端操作，但其迟到结果不会覆盖新范围页面。

这里固定的是前端确认范围和单次后端删除事务内的 ID 集合；预览与执行之间仍是两个请求，期间数据变化可能改变实际匹配数量。本轮未增加服务端跨请求范围令牌，也未自动修复此前可能遗留的消息或附件元数据。

## 后端接口

查看已删除消息：

```text
GET /api/messages?include_deleted=true&deleted_only=true
```

恢复预览：

```text
POST /api/messages/restore-preview
```

执行恢复：

```text
POST /api/messages/restore
```

彻底删除预览：

```text
POST /api/messages/hard-delete-preview
```

执行彻底删除：

```text
POST /api/messages/hard-delete
```
