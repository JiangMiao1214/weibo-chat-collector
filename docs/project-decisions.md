# 项目决策记录

更新时间：2026-08-12

## 已确认

- 当前按两个微博账号、两个微博群聊规划。
- 两个微博号的数据放入同一个数据库。
- 每条消息必须保留账号和群聊来源。
- 采集范围是群聊中所有用户的消息。
- 红包类消息不保存。
- 首次测试采集范围：最近 7 天。
- 图片和文件需要下载原件。
- 批量删除默认采用软删除。
- 手动上下文补充表单取消。
- 上下文查看、统计仪表盘、导出备份后移。
- 微博 API 任务对所有账号全局串行；所有错误零自动重试，停止后由用户沿同一任务断点人工续传。
- 普通问候正常入库；只过滤高置信度红包和粉丝群标识。
- JSON/CSV 与网页快照归入“高级工具 / 数据导入”；手机端接口研究后移。

## 初始占位约定

项目初始化阶段曾使用以下占位；实际账号、群聊和群 ID 现在通过“高级工具 / 数据导入”配置：

- 微博账号 A：`account_a`
- 微博账号 B：`account_b`
- 账号 A 对应群聊：`group_a`
- 账号 B 对应群聊：`group_b`

占位只用于种子数据，不代表当前实际绑定。
