## F4：连续上下文与逐级引用

- 在消息列表点“上下文”。右栏按旧到新展示，相同时间再按消息 ID 排序；“查看更早/更新上下文”分别向前/后拼接，重叠页按 ID 去重。

### 缺失原文的补采集

引用定位会先查同账号、同群、同删除状态的完整本地范围，不受当前日期、关键词、成员等内容筛选限制。“未找到”不等于能够断定从未采集，也可能是文字变化、删除或权限问题。不会直接访问微博尝试猜测。

未删除消息的原文未找到时，可展开“创建有界补采集任务”，填写开始/结束时间并勾选已核对范围。接口再次检查本地匹配，已匹配、歧义、无引用格式、停用/未绑定目标都会拒绝创建。

- 时间使用采集配置时区的本地时间，不带时区偏移；范围大于零且最多 7 天，结束不能晚于引用消息。
- 创建 `weibo_api_v2` 排队任务，不在请求中采集，不读取 Cookie；到达队首后仍须去“采集监控”确认关闭微博 App/网页并启动，届时检查 Cookie。
- 每次运行最多 20 页（若全局配置更低则从低）。到达上限保留已提交页和游标，停止为 `page_limit`，可人工续传；远端接口可能先经过范围外的新消息，所以 20 页不保证覆盖目标日期。
- 创建、确认、续传均不能借此绕过同账号已有风险冷却。沿用全局串行、页事务、停止与零自动重试规则。
- 同账号、同群、同范围的未完成任务不重复创建。已删除或无权限原文不能保证补回；不做无限历史追溯。

## F5：独立统计仪表盘

选择账号、群、起止日期和普通/回收站范围；查看日、周（周一开始）、月的消息数与活跃人数、类型分布、活跃成员前 50、归档状态及原件占用。当前类型分布按消息的标准类型，每条消息计一次，不把附件种类叠加成消息数量。

点击趋势日期进入相应消息范围；周/月跳转会保留原日期边界。点击成员进一步筛选。点击归档状态进入同账号/群、同消息日期范围的归档日志；事件时间与消息时间分开筛选，避免历史消息最近下载失败却被日期条件排除。

磁盘统计会检查已保存原件实际路径并读取文件大小，同一路径只计一次；按图片/视频/音频/文件/网页分别给出大小。不同分类可能引用同一原件，分类值不可直接相加代替总数。跨群共享原件在全库总数中只计一次。缺失路径另列；缓存、续传临时文件、备份、数据库和 OCR 文本索引不包含在原件数字中。

“正文已保存”和“已识别媒体全部保存”分开计数；后者只覆盖归档时已识别的资源，不代表网页中的动态内容全部抓到。未出现的日期保持未知，不插入虚假的零发言天。统计只代表本地已知数据，不声称远端历史完整覆盖。

## F6：持久化操作日志

日志记录采集创建/确认开始/停止请求/停止/续传/完成/页提交、归档状态变化与群暂停/恢复、OCR 开启/暂停/恢复/识别结果。事件与对应数据库状态变更在同一事务，失败回滚不留下“已成功”的日志。

- 支持账号、群、事件日期（UTC）、任务 ID、操作、结果、错误码，按最新事件分页，每页 50，API 最多 200。
- 事件保存机器状态码与身份字段，不保存原始异常、Cookie、Token 或 Authorization。`account_protection` 表示账号保护，`resource_failure`/`dns_fake_ip`/HTTP 等表示单资源问题，`disk_space` 表示本地磁盘保护。
- 页面和诊断 JSON 中的 URL 去除用户信息与锚点，所有查询参数值脱敏，已知签名路径段脱敏。地址是资源当前记录的原始/实际失败地址，不是每次历史重定向链的永久快照。
- 点“查看处理操作”可读取当前资源的可访问链接，精确重试该项，或确认无权访问后跳过失败链接；另可进入群归档管理。此单独入口按账号、群和删除状态校验，真实签名链接不进入诊断导出。资源被彻底删除或日志过期后不可操作。
- 采集事件可打开具体任务，刷新状态、安全停止或沿断点续传；启动仍需勾选关闭微博客户端的确认。
- 点消息编号进入正确账号、群和普通/回收站范围。OCR 事件指引回图片文字搜索页处理。

最多保留最近 90 天且 10000 条；每次新事件写入时清理过期/超量记录，删除事件不删除消息、归档或采集尝试。大量归档可能先达到数量上限。SQLite 文件不因删行立即缩小，但空间可被后续事件复用。

升级前无法重建已经丢失的事件顺序，因此各补最多 2000 个现存采集/归档状态基线，标记“升级时状态”，时间是升级记录时间，不冒充原发生时间。原有采集 attempts/pages 数据保留，可从原采集监控继续查看。导出仅包含保留期内的匹配记录。

## F7：本地图片文字搜索

### 开启与搜索

1. 进入“图片文字搜索”，选择一个账号和群。确认已归档原件可用后点击“开启本群 OCR 并补识别历史”。默认所有群均未开启。
2. 后台按批发现本群全部未删除、已保存的图片，之后已归档的新图片增量加入队列。页面显示可识别、待加入、排队、处理中、完成、失败；每 5 秒刷新，也可手动刷新。
3. 暂停阻止下一张开始，正在处理的图片结果也会在发布前重新检查；不会因为处理中点了暂停而继续写入搜索结果。恢复保留已完成结果，失败项用单独“重试识别失败项”；重试不擅自解除暂停。
4. 在图片文字关键词中搜索，显示识别片段、缩略图、本地原图入口和原消息跳转。搜索受账号/群/日期/删除状态约束；正文搜索仍只查正文。

### 实现与资源限制

- macOS 使用本机 Apple Vision（中文简/繁体及英文），不上传图像。首次启用用本机 clang 编译 `scripts/ocr_vision.m`，缓存于数据库同级 `ocr-runtime`，需要 Xcode Command Line Tools。编译/语言检查失败会明确拒绝开启，不显示虚假的工作状态。
- Windows/Linux 的本地适配支持 Tesseract，需自行安装 `tesseract`、`chi_sim` 和 `eng` 语言包并加入 PATH；此分支有调用边界，但本轮未在 Windows/Linux 实机验证。
- 全库单并发，一张完成后间隔 3 秒检查下一张，数据库租约避免多个后端进程同时领取任务。单张识别 60 秒超时；最多 4000 万像素、10 万个识别字符，不识别音频/视频/PDF，不改写原图。编译单独限 120 秒。
- 识别前校验原件路径与 SHA-256；损坏/缺失明确失败，先归档修复再重试。按账号、图片哈希、引擎版本复用文字，不跨账号复用；同账号其他群也只有自身图片关联才能检索到结果。
- `ocr_results` 单独保存文字，`ocr_jobs` 保存图片与结果关联，SQLite FTS5 trigram 做三字及以上检索，短词用范围内字面子串查找。查询是字面文本，不执行用户输入的 FTS 操作语法。
- 软删除后只在回收站 OCR 搜索中可见；彻底删除最后一个关联时清除相应文字结果和索引。原消息正文与原文件不被 OCR 修改。
- 重启后未完成租约到期会重新排队；已暂停的群保持暂停。账号/群停用、清除凭据的管理暂停也联动 OCR，重新启用不自动解除。备份包含 OCR 表和索引；恢复副本强制暂停 OCR 并释放旧租约，本机引擎程序不需要随备份复制。

Apple API 说明：[VNRecognizeTextRequest](https://developer.apple.com/documentation/vision/vnrecognizetextrequest)。开启语言校正可能改写图纸数字/字母，本实现关闭该选项，仍不能保证数字准确。
