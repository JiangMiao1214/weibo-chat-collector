## 本轮交付

参考相邻 `weibo-chat-auto/viewer.html` 的头像、连续发言、引用块和聊天阅读布局，在 collector 中独立实现 React 组件；不接入 auto 服务，不复制其 HTML 拼接、按昵称合并或短文本前缀定位逻辑。

1. 保留左侧筛选、中间消息、右侧详情，扩大桌面消息阅读区；窄屏按单列排列。
2. 日期分隔、文字头像、聊天气泡、时间、账号/群聊/消息类型，以及选中状态。
3. 同账号、同群、同用户、同日且相邻时间相差不超过 5 分钟的消息连续显示，后续发言不重复大头像；昵称相同不代表同一个用户。消息仍按接口返回的新到旧顺序，不为分组重排。
4. 点击正文、卡片空白、“详情 #编号”或附件卡片，打开原有消息详情。键盘可聚焦详情按钮并按 Enter。选择文字复制不会触发卡片选择。
5. 正文中的 HTTP(S) 地址显示域名与地址卡片，新标签打开；保留原文本，不执行消息中的 HTML，不自动访问链接、不拉取网页标题/封面。
6. 识别 `「引用内容」 - - - 回复`，单独显示引用块和回复。嵌套括号可识别外层，但内层按原文显示；格式不完整或没有明确分隔符时保留全部原文。
7. 引用提供当前列表文字匹配，以及同账号同群已入库消息的后端定位窗口，规则见下一节。
8. 附件汇总、标准类型筛选、分页、软删除预览、回收站恢复/彻底删除继续使用原有接口与范围，不因选中消息改变批量操作对象。

## 引用定位的准确边界

当前接口没有可靠的“被引用源消息 ID”字段，因此按钮叫“查看匹配消息”，而不是声称已经恢复微博原生引用关系。

- 原有“查看匹配消息”仅搜索当前已经加载的消息，包含手动加载的更早分页。
- 新增“在已入库消息中定位引用”查询同账号、同群、同删除状态的已入库消息，包含未加载分页和被日期等内容筛选隐藏的原文；独立窗口不改变原列表和删除范围。
- 候选必须同账号、同群、同删除状态，且时间严格早于引用消息；同秒无法可靠推断源顺序，不使用本地数据库 ID 猜测。
- 比较完整正文，只统一 CRLF 换行与首尾空白；不截取前 30 字，不删除正文内部空格，不跨账号/群查找。
- 列表内只有一个候选：原有按钮选中该消息、滚动定位、聚焦详情按钮，并显示“文字匹配 · 仅当前列表”。后端入口则在独立窗口展示目标及上下文。两者仍是文字匹配，不是经源 ID 确认的关系。
- 多个候选：提示无法确定原消息，不提供跳转按钮。
- 列表内没有候选：提示加载更早消息或调整筛选；后端入口没有候选时提示可能未采集、已删除或文字不同。只有显式点击后端入口才会忽略日期等内容筛选，原列表条件始终不变。
- 新加载的分页若引入重复候选，原来的唯一定位按钮会撤销。

后端完整文字匹配定位和前后各最多 5 条上下文现已实现，关闭窗口会保留原列表位置与选中消息。永久源 ID 引用关系、通用上下文翻页、多级历史导航和自动补采集仍未实现。详细状态与 TDD 证据见 [引用上下文](quote-context.md)。

## 图片和链接的边界

- 头像是昵称首字的文字头像，不请求微博头像图片。
- 图片消息显示附件数量与详情入口，未提供缩略图、灯箱、本地缓存或 Base64 入库。
- 列表接口没有每条附件的标题/URL，因此正文没有 URL 的链接消息，通过附件入口查看原有详情；不为每条列表记录额外请求详情。
- 新正文链接卡片只接受 HTTP(S)，拒绝嵌入用户名/密码的 URL。链接不自动携带账号 Cookie，也不保证微博原地址仍有效。
- 本轮没有修改现有附件原地址访问策略，不将链接可显示等同于附件已下载。

## 在 VS Code 中查看和验证

1. 打开项目根目录。如果前端开发服务已运行，刷新页面；如果没有运行，在终端执行 `npm --prefix frontend run dev`，打开终端显示的本地地址。普通查看已入库消息仍需要按 `docs/run-and-debug.md` 启动后端。
2. 点击顶部“消息”，选择账号、群聊及日期，点“搜索”。确认日期分隔、文字头像、气泡、时间与账号/群标签。
3. 点击正文或“详情”，确认选中气泡和右侧消息编号对应。使用 Tab 和 Enter 验证详情按钮。
4. 找到带 `「…」 - - -` 的引用消息。有唯一已加载文字匹配时，可点击“查看匹配消息”；原文未加载或被日期等条件筛掉时，点击“在已入库消息中定位引用”，查看独立上下文窗口。点击“返回原列表”或按 Esc 返回。
5. 切换“链接”类型，确认筛选仍有效。有正文 URL 时应看到域名卡片；否则点附件入口查看详情。访问外部链接是手动操作，本轮自动测试不访问微博或其他外部网址。
6. 切换“图片”类型，核对“含附件消息数”和“附件总数”，点击附件卡片核对详情条数。当前没有图片缩略图是已知范围，不代表下载完成。
7. 批量删除仍按当前查询结果处理，不按选中气泡处理；日常查看不要点击删除确认。删除/恢复隔离已有自动回归保护。
8. 命令面板选择 `Tasks: Run Task` → `TDD: 完整验收`。无需先启动普通服务或扫码，自动测试全部使用隔离数据。

## 代码分工

- `MessageWorkspace.tsx`：筛选、批量操作、汇总、分页及原有详情。
- `MessageTimeline.tsx`：消息卡片、正文链接、引用块、定位与键盘焦点。
- `presentation.ts`：连续分组判断、引用解析/候选索引、安全正文链接。
- `messages.css`：局部聊天样式，不修改任务监控等其他工作区样式。
- 两个同目录测试文件：组件行为和纯函数边界；`frontend/tests/e2e.test.mjs` 提供隔离浏览器回归。
