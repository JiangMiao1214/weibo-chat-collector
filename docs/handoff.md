## 当前主线

`weibo-chat-collector` 已从网页快照实验阶段转为微博 Web 内部 JSON API 采集：

- 所有账号共用一个全局串行队列。
- 新任务从 `max_mid=0` 开始；停止后沿同一任务已提交断点人工续传。
- 队首进入 `awaiting_confirmation`，关闭微博 App/网页并确认后才请求。
- 每页消息、过滤/去重、页记录、计数和下一断点在同一 SQLite 事务提交。
- 每次确认运行都写入独立 attempt；监控页可查看每次起止、断点和停止原因。
- 普通请求完成后随机等待 3–8 秒；全局每第 20 个请求完成后等待 30–60 秒并替代普通等待。
- 所有错误零自动重试、零自动恢复，失败页不推进断点。
- HTTP 429、业务码 10023/10024 冷却 60 分钟；结束后仍需人工续传。
- 高置信度红包和粉丝群标识不入库；“早上好”等普通问候正常入库。
- JSON/CSV 与网页快照位于“高级工具 / 数据导入”，不占 API 队列。
- collector 内置 Puppeteer 可见浏览器助手，负责扫码保存 Cookie、发现候选群 ID 和确认绑定；相邻 auto 仅作为已有 Cookie 文件的备用来源。
- 浏览器会话由后端单例管理，使用临时隔离用户目录，只允许 loopback 访问，并与待确认/运行中的采集任务互斥。
- collector 不调用相邻 auto 项目的 AI 分析；手机端接口优化暂缓。
