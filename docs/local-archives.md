# 图片、微博原文、视频和文件本地归档

更新：2026-09-29。新增维护、续传、缩略图、HLS 与手动正文入口见 [归档完善与操作说明](archive-maintenance.md)。

原始实现：2026-09-13。按用户确认采用原文件存磁盘、数据库存路径；历史补下载与后续新消息共用持久化队列。本功能在现有归档后端草稿基础上补齐前端、异常处理与验证，不更换采集器。

## 使用方法

1. 后端加载新代码并重启时自动增加归档表；已启动的采集应先安全停止，再手动重启后端。开发服务使用自动重载时按现有流程加载。无需重新采集聊天消息。
2. 消息页选择一个明确的账号和群聊，点击消息区顶部“本地归档”。未选账号/群、回收站及临时定位阅读时入口禁用。
3. 点击“开启本群归档并补下载历史”。范围为这个账号、这个群的全部未删除历史消息，以及之后提交入库的新消息；不受当前日期、成员、类型、关键词和噪声筛选限制。选择具体群的动作不会自动下载，开启按钮才会启用队列。
4. 状态窗口每 2 秒刷新，展示等待下载、正在下载（当前数量 / 3）、文件已保存、下载失败、等待处理和已跳过数量，列出当前下载项，以及最近 20 条错误或跳过原因；这些记录后显示可点击的原始访问链接。开启后，即使关闭窗口，后端仍会继续处理；需要停止请点“暂停归档”。暂停时不会启动新任务；小文件可能在两次刷新之间完成，因此“正在下载 0”本身不等于没有下载。
5. 网络临时失败最多尝试 3 次；登录失效、401/403/429 或磁盘空间不足会暂停所属账号已启用的群。问题解决后在对应群点击“恢复归档并重试失败项”，不会重新下载已经完成的任务。
6. 刷新消息列表/详情后，已归档图片、视频、文件和正文链接优先打开本地内容。图片旧查看入口也支持本地优先。显示“正文已保存 · N 个关联媒体未完成”时，正文可离线阅读，但仍有媒体尚未下载成功。
7. 微博正文接口明确返回“暂无查看权限”“无权查看此微博”“没有权限查看此微博”“微博已被删除/已删除/不存在”时，自动将当前任务标为“已跳过”，不写文件、不暂停账号，继续下一项。只判断错误字段，不根据正文里出现这些词作判断。登录/限流提示或已识别的认证错误码优先保留暂停保护；普通 HTTP 403、未知错误或空响应不会当作资源无权限而自动跳过。
8. 如果已经在微博网页确认链接无法访问，但接口错误不明确，可在失败/等待处理的链接旁点击“跳过此链接”。操作只影响这一项，保留暂停状态；需要继续下载时再点“恢复归档并重试失败项”。普通恢复/重新开启不会重试已跳过项；可用新增“重新下载此项”显式重试。跳过不等于已保存，原消息和远端链接保留。

实际历史下载需用户选择目标群并启用；本轮自动验证不会启用真实群、访问真实 Cookie、采集或下载真实文件。

## 保存什么

| 来源 | 保存结果与离线方式 |
| --- | --- |
| 图片 | 下载地址返回的原始字节，不缩小、不转码；本地路由直接显示。校验 MIME、文件头、接收长度（源站提供时）和 SHA-256。不是承诺发送者上传前的最高分辨率原图。 |
| 视频/音频文件 | 直接返回的媒体文件保存原始字节，通过本地路由播放；支持浏览器可播放的 MP4/WebM 等，实际播放能力取决于浏览器编解码器。 |
| 普通文件 | 原始文件保存；本地打开入口作为文件下载，避免在应用域执行不可信文档。 |
| 微博原文 | 常规 `weibo.com/用户ID/微博ID`、`m.weibo.cn/detail/ID` 或 `/status/ID` 地址读取正文、长文、转发正文，并排队下载可识别图片和直链视频。保存不含可执行脚本的 JSON 快照，由本地服务渲染为无脚本页面。 |
| 微博个人主页 | `weibo.com/u/用户ID`（含 www）通过用户资料接口保存昵称、用户 ID、简介、地区及认证说明，存在头像时加入图片队列。标题明确标注“个人主页资料快照”，不下载该用户全部微博、不归档动态信息流。接口必须返回匹配 ID 和有效昵称，否则显示失败。 |
| 短链接 | 逐跳跟随公网地址；落到受支持的微博原文则使用微博正文适配，否则按文件或网页处理。 |
| 微博外链包装 | `weibo.cn/sinaurl?u=目标地址` 先解出唯一目标，再执行地址校验和对应归档适配；不把中转页当作原文。支持最多 4 层包装，拒绝无目标、多目标及过深嵌套。 |
| 普通网页 | 保存服务器返回 HTML 中提取的文字，以及可识别的图片、视频和 PDF/Office/ZIP 附件地址对应的资源；不执行远程脚本。 |

当前边界：这不是完整网站镜像，不抓评论/点赞列表，不承诺复制网页排版与交互。JavaScript 动态网页、第三方登录页、未识别的微博播放页、不支持结构的 HLS、DASH 分段流、DRM、已删除原文或过期地址不保证可归档；已识别的不支持格式/不完整响应显示失败，不将网页壳冒充视频或完整微博。第三方网站不会接收微博 Cookie，也不读取用户浏览器其他站点登录态。通用网页文字提取不能保证理解所有站点的登录/验证页，需检查实际快照内容。

只保存原文而关联媒体还在排队/失败时不会在消息入口表示全部完成。原文保存时间为快照下载时点，之后远端编辑不会自动覆盖该存档。

## 文件与数据库

默认根目录使用现有 `ATTACHMENTS_DIR`，默认即 `data/attachments`。归档相对路径：

```text
archives/<账号ID>/<SHA-256前两位>/<完整SHA-256>
```

物理文件名使用哈希（不依赖网址和扩展名），文件类型、大小、原 URL、消息关联与相对路径存数据库；通过应用查看时返回 MIME 和下载文件名。相同账号内字节一致的文件共用一份；不同账号保持分开，不使用感知哈希合并相似图纸。文件不存入 SQLite BLOB 或 Base64，另按需生成独立缩略图，原件不变。

每次下载写临时 `.part-` 文件，流式计算哈希，刷盘后原子发布；原件临时写入失败时清理；支持续传的临时数据在网络失败/暂停时可保留，最终记录事务成功才显示已保存。不会因为失败文件改变消息采集页的事务和游标。完成文件跳过；有验证器的直链媒体支持 HTTP Range 字节续传，服务器不支持时重新下载。进程被强制杀死可能留下孤立临时文件，程序不会自动清理已有原件。

备份应同时包含数据库和整个附件目录；仅拷贝数据库不能恢复图片。归档路由拒绝越出归档根目录或访问另一账号目录；普通/回收站继续隔离。软删除隐藏消息但不删除文件；彻底删除清除关联归档元数据，磁盘原件仍保留，沿用现有删除契约。文件缺失时明确提示恢复备份，不悄悄联网替代。已标记 stored 的文件缺失/损坏后，可用“检查并补下载缺失或损坏文件”显式重排，或恢复完整备份。

## 队列与资源限制

- 按群持久启用，扫描每批 100 条已提交消息；正文 URL、附件 URL、已保存分享元数据中的链接均加入队列，同消息/同 URL/同类型只建一项任务。
- 全局一个归档协调器持租约，每批最多 3 项通过独立线程同时下载；本批全部结束后等待至少 5 秒再开启下一批（不会在本批某一项先完成时立即补第四项）。领任务与状态更新在 SQLite 事务内完成，各下载线程独立数据库连接；其他后端进程不能同时领取新批次。同一账号发生登录/限流暂停后，同批其他任务在下一次检查时中止并回到等待状态，不标记保存成功；已阻塞的网络读取需要等待返回或超时（通常上限 30 秒）。进程重启/租约过期后恢复未完成任务，旧持有者不得写入新持有者的任务结果。发现采集任务 running/awaiting_confirmation 时先让采集处理，不启动下一批归档。
- 图片/音频上限 10 MiB，普通网页 HTML 上限 2 MiB，视频/文件上限 20 MiB（沿用二进制单位，1 MiB = 1,048,576 字节）。恰好达到上限允许保存，超过上限停止并清理本次临时文件，不标记已保存；没有 Content-Length 时也按实际接收字节检查。普通链接或文件入口返回图片/音频 MIME 时，同样执行 10 MiB 上限。HTML 限制针对收到的原始 HTML，关联资源各自计限。微博 JSON 响应上限 8 MiB。每次正文最多 100 个关联资源，超出时提示失败。
- 网络连接/读取超时 30 秒，单次响应读取最长 30 分钟；最多跟随 5 次请求，逐跳验证 DNS 并固定连接目标 IP。默认只连接公网 IP；下述已支持的 HTTPS 域名兼容代理 Fake-IP。禁止私网、回环、带用户名密码和非标准端口，微博 Cookie 按域/路径和账号重新生成，不随跳转发送给其他域。
- 剩余磁盘必须至少保留 256 MiB 加当前写入块；不足时暂停账号。正常原件不会自动淘汰。库事务失败可能留下无引用的完整文件，后续同内容下载会复用。

### 代理 Fake-IP 与地址错误

部分代理会将正常域名解析成 `198.18.0.0/15` 范围的虚拟 IP。旧版将这种情况与错误端口统一显示为“不支持此地址：仅允许公网 HTTP(S) 标准端口”，可能导致所有微博图片和正文都失败。

现支持以下域名通过 HTTPS 标准端口使用该范围的代理映射：`weibo.com`、`www.weibo.com`、`m.weibo.cn`、`upload.api.weibo.com`、`t.cn`、`weibo.cn`、`face.t.sinajs.cn`、`i2.hdslb.com`、`gaoshanwen.com`，以及 `sinaimg.cn` / `sinaimg.com` 的子域名。本轮新增项来自失败任务中的外链中转、微博表情、哔哩哔哩封面和目标文章站点，使用精确域名匹配，不放开任意第三方站点。连接仍固定本次解析的 IP，以原域名进行 TLS 证书和主机名验证，然后才发送请求。每次跳转重新校验，第三方站点和图片 CDN 不接收微博 Cookie。

上述兼容域名的旧 HTTP 标准端口地址，会在发送任何请求之前转换为 HTTPS（显式端口 80 同时移除）；路径和查询参数保留，不回退至明文连接。这解决旧 `http://t.cn/...` 及外链目标使用 `http://weibo.com/...` 时的拦截。归档任务保留原始 URL，因此旧失败任务、消息入口和本地文件关联不需要改写数据库。

此兼容不放开通过明文 HTTP 连接 Fake-IP、其他域名、直接填写的虚拟 IP、私网/回环地址或混有私网地址的 DNS 结果。其他域名出现 Fake-IP 提示时，可在失败项确认设置精确域名 HTTPS 兼容，或配置为真实公网 DNS 后重试。非法端口、非公网 DNS 和未支持的 Fake-IP 现在分别显示具体原因。

修复后加载新后端代码，再在原群窗口点击“恢复归档并重试失败项”；已有失败任务会重新排队，已保存项保持完成。手动暂停状态不会因代码更新自动解除。

## API 与表

- `GET /api/archives/status?account_id=1&group_id=11`：只读状态、按状态计数和错误摘要，不启动下载。
- 状态响应 `active_jobs` 列出本群当前最多 3 个下载项（任务 ID、消息 ID、类型、原始 URL）；`errors` 同样增加 `source_url`。按账号/群/删除状态隔离，非法或带凭据的 URL 不作为可点击地址返回。前端对链接再次校验，长地址可换行；source_url 是原始保存地址；新增 failure_url 在已捕获时提供实际失败跳转地址。
- `POST /api/archives/control`：`{account_id, group_id, action: start|pause|resume}`。ID 正整数、账号群匹配；参数不合法 422，错范围 404。开启/恢复从历史头部再次发现遗漏任务，已完成项不重复入队。
- `POST /api/archives/{job_id}/skip`：`{account_id, group_id}`，只允许当前范围内未删除消息的失败/等待处理链接；已保存、排队或下载中项返回 409，跨范围/已删除返回 404。重复跳过幂等，保留原暂停状态，不触发下载。
- `GET /api/archives/{job_id}/content?account_id=1&group_id=11&deleted_only=false`：仅本地读取，未完成 409，错范围/缺失文件 404；正文返回转义 HTML、本地媒体地址和严格 CSP，其他内容返回文件响应。
- 列表与详情新增 `archives` 元数据：任务 ID、消息 ID、URL、kind、status、pending_resources。不会返回 Cookie 或原始响应。
- 新表：`archive_groups`（启用、暂停、扫描位置）、`archive_jobs`（下载状态与本地路径）、`archive_runtime`（全局租约与节流）、`archive_resources`（正文和媒体多对多关系）。启动迁移可重复执行。
- `archive_jobs.status` 增加 `skipped`（现有 TEXT 列无需迁移）；`error` 存脱敏固定跳过原因。已跳过项不提供本地内容，关联子资源跳过仍计入未完整保存数量，不能冒充完整归档。状态 API 的原因条目增加 `status`，供前端判断是否显示单项跳过按钮。

## 测试记录

本轮开始时已有后端草稿及 10 个归档测试，前端两个归档用例尚因入口缺失/仍走远端链接失败，类型和重复函数门禁未通过。保留已有草稿与断言，未将其描述为本轮重新看到的后端红灯。

新增业务红灯覆盖：删除发生在最终提交前、正文共用媒体仍未完成、再次开启后 blocked 任务卡住、错误图片字节被保存、转发长文未支持、文件路径跨账号、分享元数据链接遗漏、前端超时被轮询无限延长。分别实现、重跑通过；其他正常行为补充绿灯回归。

本轮没有提高质量基线、删断言、增加 skip、修改 verify 或变异门槛。安全 URL 和归档元数据拆成独立共享模块，消除已有草稿重复函数与依赖环风险；前端请求响应校验拆分以满足复杂度上限。原浏览器流程扩展归档开启/暂停/恢复、Esc 焦点和桌面/390px 窗口检查，所有接口模拟、禁止测试下载到系统目录。


最终验收：`.venv/bin/python scripts/verify.py --fast` 和 `.venv/bin/python scripts/verify.py` 均 PASS。127 个后端测试（归档相关 22 个）、62 个前端测试、4 个浏览器助手、6 个门禁自测、4 个浏览器入口测试、4/4 定向变异，类型/构建/结构检查均通过。桌面与 390px 归档窗口截图已检查，无窗口横向溢出；截图位于 `.tdd-results/ui/archive-desktop.png`、`archive-mobile.png`。报告分别在 `.tdd-results/fast/report.json` 与 `.tdd-results/full/report.json`。

最终无失败检查；真实微博端点、真实视频/文件格式、Safari 实机、真实历史库批量下载及大库性能未执行。本次未提交/推送、未新增代理、未启用真实群归档、未读取真实 Cookie。测试初期草稿失败及中途复杂度 21 > 20 已通过实现与拆分修复，未放宽基线。

### 2026-09-13：调整单个资源的归档大小上限

按用户要求将照片/音频调整为 10 MiB、HTML 调整为 2 MiB、视频/文件调整为 20 MiB。限制在归档下载时生效，已保存原件无需重新下载。普通链接和文件入口也结合响应 MIME 执行媒体上限。

先新增 2 个边界测试，旧实现出现 12 个业务子用例失败（超过新上限仍能保存）；更新实现后 8 个下载测试全部通过。覆盖恰好上限、超出 1 字节、HTML 缺失 Content-Length、链接返回不同媒体类型，以及失败后不留下临时文件或额外原件。

快速检查与完整验收均 PASS：129 个后端、62 个前端、4 个浏览器助手、6 个门禁自测、4 个浏览器入口测试、4/4 定向变异，类型/构建/结构检查通过。无最终失败项；全部使用临时文件、隔离数据库及模拟网络，未执行真实文件下载或在线采集。未更改检查规则或质量基线。

### 2026-09-13：修复代理 Fake-IP 导致的统一地址拒绝
